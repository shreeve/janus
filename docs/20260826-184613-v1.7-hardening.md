# Janus v1.7 hardening and throughput addendum

Status: authoritative addendum for v1.7.0. Where this document conflicts with
an older capability document, this document describes the shipped behavior.

## Scope

This revision follows a request/response audit of all nine Janus capabilities.
It does not add a tenth capability. It removes avoidable shared work,
closes reload and teardown races, and strengthens the release path while
preserving the existing capability boundaries.

## Data-plane request path

A site handler now normalizes the authority, resolves the hot registration,
and validates the request path at most once. The resulting `AppRecord`, host,
and decoded path are passed to auth, hub, files,
browse, and proxy continuations as needed. Direct unit seams retain wrappers
that perform their own validation.

Least-connections selection is serialized by a mutex shared by snapshots of
one registration. Unrelated apps no longer acquire a process-wide selection
mutex. The socket-state map has a separate lock used for map membership and
lazy proxy initialization; inflight and passive-health fields remain atomic.
Doorbell single-flight synchronization remains process-wide by app ID and is
not part of ordinary worker selection.

## Capability corrections

### Control

Control listen URLs reject user information, query strings, fragments,
percent-escaped paths, wildcard path syntax, and non-canonical paths. Fixed
listeners with the same effective numeric/wildcard/localhost bind are rejected
before Start. Each listener serves only the base path on its own listen URL.

### Hub

Membership mutation and recipient resolution linearize under the per-app hub
lock. Serialization and bounded recipient-queue admission happen after that
lock is released, so one slow queue cannot stall unrelated membership work.
A trusted kick frame and its close are admitted atomically to preserve their
ordering. Ping write failures close immediately. Bridge attachment is fenced
against concurrent connection teardown.

Bridge request snapshots remove all standard hop-by-hop headers, the headers
named by `Connection`, `Proxy-Authorization`, `Proxy-Authenticate`,
`Proxy-Connection`, and every `Sec-WebSocket-*` field, case-insensitively.
Retained value slices are copied so later request mutation cannot alter the
snapshot.

### mDNS

The pooled advertiser records configuration ownership and an epoch. A rejected
reload restores its predecessor configuration; stale responder operations
remove their handles and cannot publish into a newer or rolled-back epoch.
Successful handoff clears predecessor references. Normal configured-name and
app-name front-door checks use direct entry-key lookup; only conflict-renamed
effective names scan live responder handles.

### Auth

Sessions are bound server-side to the normalized host that minted them. Gate
authorization and the sliding-idle refresh happen in one HMAC lookup and one
store critical section. Open paths, disallowed gates, and login/status-page
polling do not refresh idle lifetime. Wildcard and catch-all Caddy routes still
require a hot registry claim before exposing a login surface; exact configured
hosts and cold browse hosts remain explicit cold admission.

Reload reconciliation is staged during Start and applied only after Caddy has
installed the successor. A rejected generation cannot revoke sessions or
close hubs. Committed reconciliation retains a session only when its user is
still enabled on a site matching the session's minting host.

Redirect targets are parsed and exactly-once decoded before gate-prefix
checking. Reserved request and response cookies are scrubbed without rewriting
the bytes of unrelated quoted cookies, including before Flush, Hijack, or an
upstream response commit.

### Files and browse

The handler validates the URL path once. Cold-root descriptors are prepared at
Provision; the common hot registration (four roots or fewer) resolves root
descriptors into stack storage instead of allocating a slice. Root opens,
file stats, directory reads, and renderer subprocesses remain deliberate
freshness and containment boundaries.

### Access observation

Every eligible completion still consumes one registration sequence and updates
publication accounting. When no subscriber exists, Janus validates the
invariant-bearing completion fields but does not construct or JSON-encode an
undeliverable access event. A subscriber attaching afterward observes the
advanced head and receives the existing no-replay gap semantics.

On the retained Apple M5 run (macOS 26.6.2, Go 1.27.0), command:

```text
go test -run '^$' -bench '^BenchmarkAccessEncoderBridge/(json-baseline|no-subscribers|one-draining-subscriber|four-subscriber-fanout)$' -benchmem -benchtime=500ms -count=3 .
```

Median results were:

| Case | ns/op | B/op | allocs/op |
| --- | ---: | ---: | ---: |
| JSON baseline | 559.8 | 1,425 | 8 |
| Janus, no subscribers | 875.5 | 2,395 | 15 |
| One draining subscriber | 2,311 | 3,736 | 24 |
| Four-subscriber fan-out | 2,540 | 3,736 | 24 |

The no-subscriber incremental cost is therefore about 316 ns, 970 bytes, and
seven allocations on this run. The 2026-08-01 retained run measured about
1,284 ns, 1,959 bytes, and fifteen allocations over its baseline. The runs use
the same Apple M5 benchmark corpus but different Go and macOS patch versions,
so the comparison is directional rather than a controlled toolchain A/B.

## Reload, shutdown, and ownership

`Stop` and `Cleanup` share one idempotent generation-resource teardown.
Cleanup therefore closes control and dedicated-mDNS listener handles, stops
servers, cancels browse work, and detaches access streams even when Caddy
rejects a candidate after Start without calling Stop. It then releases pooled
state. The last pooled-state
destructor closes idle proxy transport connections.

The heartbeat TTL minimum is 3 ms, matching three times the 1 ms defensive
sweeper floor. Request authorities require decimal ports in 1..65535;
bracketed hosts must be IP literals, and IP authorities resolve only exact
registrations.

## Release and acceptance

Unix release archives include `install.sh`. It preserves an existing target
directory's permissions, stages the complete binary beside the destination,
and atomically renames it into place. It never installs or overwrites a live
Caddyfile.

The release workflow uses read-only repository contents by default and grants
write only to the publishing job. Unit, vet, race, full macOS acceptance,
cross-platform build, package, installer, module-list, version, and checksum
gates precede publication. Manual workflow runs package as `v0.0.0-dev` and do
not publish a release.

The acceptance harness owns only per-run state, refuses occupied fixed ports,
checks process command lines before signaling recorded PIDs, scopes Rip worker
cleanup to the recorded manager, and removes a tenant directory only after
proving it is the expected `janus-tenant.*` child of the configured temporary
directory.

## Upstream binary-scan residue

`govulncheck ./...` reports zero reachable vulnerabilities in Janus source.
Scanning the assembled Caddy 2.11.4 binary also reports GO-2026-6094 in
`github.com/google/cel-go` 0.28.1 and GO-2026-5932 for the unmaintained
`golang.org/x/crypto/openpgp` packages pulled into Caddy's standard module set.
Caddy 2.11.4 does not compile against cel-go 0.30.0, the advisory's fixed
version, and the OpenPGP advisory lists no fixed version. These are upstream
binary dependencies rather than Janus call paths; the release does not hide or
misstate them.
