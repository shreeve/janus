# Capability: auth (URL-prefix gates for auth-less apps)

> **The written contract for capability 6 — the contract the
> implementation lands against.** Owner rulings 2026-07-28 (including
> post-review answers). Cold Caddyfile: a shared **`users`** table, one
> or more **`gate`** path prefixes that name who may pass, one
> host-wide session (sign in once / sign out once). Cascades, version-`a`
> passhashes, pooled sessions, `__Host-janus`, strip-and-inject
> `Remote-User`, and observe-and-revoke `/1.0/auth` are in scope below.

| | |
| --- | --- |
| **Order** | **6** (after **ping**, **control**, **cache**, **hub**, **mdns**) |
| **Surface** | Cold config for users and gates; sessions and counters on hot `/1.0/auth` (observe and revoke only) |
| **Cascades** | **Yes** — global default → site override; explicit `off` beats inherited on; built-in default off |
| **Built-in default** | off (unset at every level → no auth) |
| **Module** | Site handler check between ping and hub interception; `auth.go`, `auth_config.go`, embedded `auth.html`; hot surface in `control_auth.go` |
| **Directive** | Global `janus { auth { … } }` for the process default; site `janus { auth … }` to override |
| **Status** | **Shipped** — lands on `main` (PR #4); Go tests and `./test.sh` auth group pin this contract |

**Naming.** The capability is `auth`. Credentials live under **`users`**.
The unit of path protection is a **`gate`** (path prefix). The login
door for a gate is the exact path `{prefix}auth` (for `/one/` →
`/one/auth`). The host comes from the Caddy site block — gates do not
carry hostnames.

## Why it exists

Auth-less apps need a door at the edge, not an identity provider.
Operators lock **parts** of a host (e.g. `/one/`, `/foo/bar/baz/`)
while leaving other paths open. Users are defined once; each gate
lists who may enter. A person signs in **once** on the host and may
use every gate that lists them; they sign out **once**.

**Not an identity provider.** No roles, groups, OIDC, OAuth, or
directory sync. One flat `users` table, per-gate allow lists, one
yes/no wall, one `Remote-User` header.

## Scope

| Piece | Where | Role |
| --- | --- | --- |
| `janus { auth { … } }` | Global options | Process-wide default users + gates |
| `janus { auth … }` | Site block | Site override: `auth off`, or a full `auth { … }` that **replaces** the global auth config |

**Host selection.** The site address selects the host. A `gate`
argument is a **path prefix only**.

**Perimeter.** Guarded upstreams must be reachable only through Janus
(unix sockets / localhost listeners). Operator obligation.

## Users and gates

### Users (shared)

All credentials for the effective auth config live in one `users`
block. Each line is `user <name> <passhash>` (or a compact `users { … }`
listing — see Syntax). Version-`a` blobs are 32 chars: `a` + 31 base62. Names: lowercased; `[a-z0-9._-]{1,64}`.

### Gates (path allow lists)

```caddyfile
auth {
	users {
		alice a…
		bob   a…
		larry a…
	}
	ttl 8h
	gate /one/ {
		alice larry
	}
	gate /foo/bar/baz {                 # normalized to /foo/bar/baz/
		bob larry
	}
}
```

- **Normalize prefix:** if the path does not end in `/`, append `/`.
- **Match:** request path is under the gate when it equals the prefix
  without the trailing slash, or continues with a `/` segment boundary.
  For `/one/`: `/one`, `/one/`, `/one/two` match; `/ones` does not.
- **`gate /`:** matches **every** path on the host (whole site). Login
  door is exact **`/auth`**.
- **Overlap:** **longest prefix wins**.
- **Allow list:** the gate block names users who may pass. Every name
  must exist in `users`. Empty allow list → provision hard error.
- **Outside every gate:** no auth wall on that path (open), subject to
  strip/421 rules below.
- **`/ping` and `/ping/`:** **always exempt** when the site's effective
  ping is on.

### Session model (host-wide)

- One session cookie for the host: **`__Host-janus`**, `Path=/`.
- Session value: `{user, issuedAt, lastSeen}` — **not** bound to a
  single gate.
- **Sign in once / sign out once:** any successful login on any gate
  door mints (or replaces) the host session; sign-out clears it for
  the whole host.
- **Authorization:** a request under winning gate G proceeds only if
  the session's user appears in **G's allow list**. Same user on two
  gates → both paths work after one login.
- **Login door authorization:** `POST` to `{prefix}auth` succeeds only
  if the verified user is in **that gate's** allow list (you cannot
  mint a session from a door you are not allowed to use). `GET` the
  door still shows the login form when unauthenticated.
- **TTL:** one sliding idle timeout for the session (auth-block
  `ttl`, default 8h), refreshed on any authenticated request under
  any gate. When idle expiry hits, the session is dead **everywhere**
  on the host.

### Login-door integrity

- Exact path `{prefix}auth` only — no trailing slash variant as the
  door (`/one/auth/` is ordinary gated traffic, not the login
  endpoint).
- Exact `{prefix}auth` is **reserved** for the wall; the app never
  serves it while the gate exists.
- **Hard error at parse** if any gate prefix would shadow another
  gate's login door under longest-prefix rules (e.g. `/one/` together
  with `/one/auth/` is illegal).

## Cascade

| Global | Site | Effective |
| --- | --- | --- |
| (unset) | (unset) | **off** |
| `auth { users… gate… }` | (unset) | **on** — inherit global config |
| `auth { … }` | `auth off` | **off** |
| (unset) | `auth { … }` | **on** — site config only |
| `auth { … }` | `auth { … }` | **on** — site config **replaces** global (no merging of users or gates) |
| any | bare `auth` / `auth on` | **on** — **inherit** global gates/users (same as unset site auth when global is on) |
| any | `auth { }` (empty block) | **provision error** |

**Effective auth on** means the resolved config has a non-empty `users`
table and at least one gate. Missing either → provision hard error.

## Cold config

### Syntax

```caddyfile
{
	janus {
		control local
		auth {
			users {
				alice aZoyWD0mfNZH7GZCh3DH9Te1FwAxA0yc
				bob   aI9eoj7z2M0oTFWY3ai7uQzblQR2spHF
				larry aTsNAccM4EGpfEd4HaZMzNc4KJ63yeD1
			}
			ttl 8h
			gate /admin/ {
				alice bob
			}
		}
	}
}

app.ripdev.io {
	import ripdev_tls
	janus {
		auth {
			users {
				alice a…
				bob   a…
				larry a…
			}
			gate /one/ {
				alice larry
			}
			gate /foo/bar/baz {
				bob larry
			}
		}
	}
}

open.ripdev.io {
	import ripdev_tls
	janus { auth off }
}
```

### Legal lines

```text
auth
auth on                              # inherit global (when used at site)
auth off
auth {
	users {
		<name> <passhash>             # version-a; repeatable
	}
	user <name> <passhash>            # alternate: repeatable at auth level
	ttl <duration>                   # optional; one session idle TTL
	gate <path> {                    # allow list; names must exist in users
		<name> …                     # multiline block required (Caddyfile)
	}
}
```

Gate allow lists **must** use a multiline block — Caddyfile rejects
tokens after `{` on the same line, so `gate /one/ { alice larry }` is
illegal. Write:

```caddyfile
gate /one/ {
	alice larry
}
```

`users { name <passhash> }` and top-level `user name <passhash>` lines are
equivalent ways to fill the same table; mixing is allowed; duplicate
names in one config are a hard error.

### Defaults

| Knob | Default |
| --- | --- |
| capability | off |
| `ttl` | 8h (one host-wide sliding idle) |
| Cookie | `__Host-janus` — fixed, `Path=/` |
| CSRF cookie | `__Host-janus_csrf`, 600 s — fixed |
| KDF | argon2id version-`a` constants (m=64MiB,t=2,p=1; 8+15 B; base62) |
| Login throttle | ladder below |
| Throttle map bound | 65,536 (expired swept first; **ban entries are not casually evicted** — prefer refusing new non-ban entries at cap) |
| Argon2 concurrency / queue | 2 / 16 |
| Body / user / password caps | 64 KB / 256 B / 1024 B |
| `to` length cap | 2048 B |

### Hard errors (parse)

- Unknown arguments; `auth off { … }`; duplicate `auth` in one block
- `gate` without path or without allow-list block; empty allow list
- Gate path empty, not starting with `/`, containing `//` or `..`
- Duplicate gate prefixes after normalization
- Gate allow-list name not present in `users`
- Login-door shadowing (above)
- Duplicate / illegal usernames; malformed passhash; non-positive `ttl`
- Empty `auth { }`

### Hard errors (provision)

- Effective on with empty `users` or zero gates

## The `{prefix}auth` endpoint

Exact path. State machine:

| Request | Session | Response |
| --- | --- | --- |
| `GET`/`HEAD` `{prefix}auth` | none / invalid | Login form (+ CSRF); optional `to` |
| `POST` sign-in | any | CSRF → throttle → argon2; user must be in **this gate's** allow list; success mints/replaces host session; **303** to sanitized `to` (default = this gate's prefix); failure re-renders (401) |
| `GET`/`HEAD` `{prefix}auth` | valid | Status + sign-out; re-mints CSRF |
| `POST` sign-out | any | CSRF; clear host session; **303** to `{prefix}auth` |
| other methods | — | **405** + `Allow` |

**`safeTo`:** same-origin path only; must stay **under this gate's
normalized prefix**; anything else collapses to that prefix. (After
login the user may still navigate to other gates they are allowed on;
the redirect target itself cannot escape this gate.)

CSRF double-submit, cookie flags, body caps, and sign-in vs sign-out
POST predicate match the hardened login posture (embedded
`auth.html` + server checks).

## Unauthenticated requests under a gate

Path matches a gate, is not that gate's exact `{prefix}auth`, and has
no session whose user is in that gate's allow list:

| Shape | Response |
| --- | --- |
| Browser-shaped GET/HEAD + `Accept` has `text/html`, not WS upgrade | **302** → `{prefix}auth?to=<path+query>`, `Cache-Control: no-store` |
| Everything else | **401**, `no-store`, no `WWW-Authenticate` |

Hub upgrades under a winning gate need an authorized session (else
401). Hub paths outside every gate are untouched by the wall.

## Login throttle (ladder)

Before any argon2 work. **Per gate** (the login door being posted to).

| Key | Use |
| --- | --- |
| `(client key, username)` | Ladder delays |
| `client key` alone | 24h ban **and** aggregate failure budget |

Client key: peer `RemoteAddr` (never `X-Forwarded-For`); IPv6 → `/64`.

| Failed attempt # | Behavior |
| --- | --- |
| 1–3 | Immediate failure (no added wait) |
| 4 | Further tries **429** + `Retry-After` until **10s** after the 4th failure |
| 5 | Wait **60s** |
| 6 | Wait **300s** |
| 7+ | **24h** ban for this client key on this gate |

**429 wait does not increment** the attempt counter.  
**Aggregate:** excessive failures across *different* usernames from the
same client key on the same gate advance a parallel client-level
budget into the same ladder/ban (username spray cannot dodge
indefinitely). Exact aggregate thresholds match the same 1–3 / 4 / 5 /
6 / 7+ steps counting **all** failed posts from that client key to
that gate.

Successful login clears that client+username pair state and the
client aggregate for the gate. Ban is time-based; it is not cleared by
other usernames succeeding. Map bound: sweep expired first; do not
arbitrarily evict active ban rows.

Dummy-hash equalization, constant-time compares, argon2 semaphore 2 /
queue 16 remain.

## Strip scope and plain HTTP

When the site's effective auth is **on** (any gates):

1. **Strip on every fall-through** (gated or open): remove
   `__Host-janus` and `__Host-janus_csrf` from the proxied request and
   from the hub header snapshot; strip client `Remote-User`; if the
   request is authorized under a gate, inject `Remote-User: <user>`
   and set the cache-bypass signal.
2. **Plain HTTP → 421** for **any** path on that site (`r.TLS == nil`),
   with the plain body that auth requires HTTPS. Once-per-site ERROR
   log. Open paths are not exempt — `__Host-` cookies require HTTPS
   for the whole host story.

Upstream `Set-Cookie` for the reserved `__Host-janus*` names is
rejected/stripped on responses when effective auth is on (apps must
not clobber the wall).

## Sessions (store)

Pooled in-memory store keyed by HMAC(token); reload keeps sessions;
restart wipes them. Token 128-bit `crypto/rand`; never client-proposed.

**App Start revocation:** sessions whose user no longer appears in the
resolved `users` table are revoked. Losing a gate allow-list entry
does not revoke the session — that user simply can no longer pass that
gate.

## Handler ordering

1. mdns front-door decider (auth inert there)
2. ping (`/ping` exempt when ping on)
3. **auth** — 421 if effective on and no TLS; else gate match / login
   door / wall; strip rules; fall through
4. hub
5. cache / data plane

Capability order **6** is the cold landing order among capabilities;
request order is ping → auth → hub → cache as above (auth never runs
after cache for a gated request).

## Hot surface (`/1.0/auth`)

Observe and revoke only.

- **`GET /1.0/auth`** — `enabled`, sites, session count, counters
  (`logins`, `login_failures`, `throttled`, `banned`, …).
- **`GET /1.0/auth/sessions`** — each row always includes at least:
  `id`, `user`, `host`, **`gates`** (array of normalized prefixes whose
  allow lists currently include this user), `age_ms`, `idle_ms`.
- **`DELETE /1.0/auth/sessions/{id}`** — unique id-prefix → 204;
  none → 404; ambiguous → 409.
- **`DELETE /1.0/auth/sessions`** — wipe all.

`GET /1.0` includes `"auth": true` when any site has effective auth.

## Behavior summary

| Row | Contract |
| --- | --- |
| Off | No wall; no strip/421 from auth |
| Path outside gates | No login required; strip/421 still apply if auth is on |
| Under gate, authorized user | Fall through + `Remote-User` + cache bypass |
| Under gate, no/wrong user | 302 or 401 |
| `{prefix}auth` | Login / status / sign-out |
| One login | Host-wide session; all allow-listed gates |
| Idle TTL exceeded | Session dead for the whole host |
| `/ping` | Exempt when ping on |
| Plain HTTP | Site-wide 421 when auth on |
| `gate /` | Whole host; door `/auth` |

## Non-goals

- Identity-provider features
- Registry-delivered credentials
- Guarding the mdns plain-HTTP front door
- Hostnames inside `gate` arguments
- Path-scoped session cookies
- Merging users/gates across cascade levels
- Per-gate session cookies or per-gate idle clocks

## Acceptance pins (minimum)

Parse/provision errors; cascade inherit/replace/off/empty; normalize
`/`; `gate /`; longest prefix; login-door shadow hard error; host-wide
session + per-gate allow lists; `safeTo` under minting gate prefix;
ladder + aggregate + ban; site-wide strip and 421; reserved cookie
response strip; `/ping` exempt; hub under gate → 401 without session;
hot sessions carry `host` + `gates`; `test.sh` auth group uses prefix
gates.
