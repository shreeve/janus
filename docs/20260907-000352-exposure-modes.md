# Exposure modes: the front-door contract and how each platform holds it

Status: authoritative for the service edge from v1.13.0. The operator
surface is in `README.md` (Exposure modes); this record is the contract,
the reasoning that fixed it, the measurements that proved it, and the
doors that were closed on the way so they are not reopened.

## The contract

The service edge listens on ports 80 and 443 at exactly the addresses its
mode names, and at nothing wider, on every platform that supports the
mode:

| Mode | Addresses | Promise |
| --- | --- | --- |
| `localhost` | `127.0.0.1`, `::1` | this machine only; the default, and the only mode that can make an absolute promise |
| `lan` | localhost plus one private IPv4 address of one interface | this machine and its on-link network; private addressing keeps the internet out without any rule |
| `wan` | every interface | whoever the network lets through; it prints that wildcard exposure is active |

Three properties follow from the contract and everything below serves them:

- **One source of truth.** The mode is `scope.json` in the state directory,
  written only by its owner. Every verb that adapts the service Caddyfile
  (`run`, `reload`, `validate`, `adapt`) derives `JANUS_BIND` from it in its
  own process before Caddy reads `default_bind {$JANUS_BIND}`. Nothing else
  may set that variable; the env file refuses a `JANUS_BIND` line.
- **Fail closed.** An absent scope is `localhost`. A scope file that does
  not parse, or names an address the host cannot realize, stops the edge
  rather than widening it. The edge reads its own sockets (via `/dev/fd`)
  against the stored mode at start and every two seconds and exits on a
  violation seen twice; a supervisor restarts it into the same refusal
  until the file or the mode is fixed.
- **Never overclaim.** `janus status` reports the scope, the bind, the
  firewall verdict, and each front-door address labeled by what enforces
  its reach. Without root on macOS the firewall is `missing` when the
  files are absent and `unverified` otherwise; only root says `verified`,
  after checking that pf is enabled and holds exactly the anchor's rules.

## What holds the contract, per platform

**Linux** binds the exact addresses. `lan` needs no firewall because a
private address is unreachable from the internet by addressing alone, so
the mode change is a bind change and never needs root. A lan edge whose
address moved cannot bind and exits; the system unit has no start limit,
so it retries until `janus mode lan`, run again, stores the new address.

**macOS** cannot bind an exact low port without root, so the socket is the
wildcard in every mode and pf scopes it. The anchor (`/etc/pf.anchors/janus`,
declared and loaded from `/etc/pf.conf` ahead of Apple's filter anchor so
its `quick` rules are final) is:

```
pass in quick inet proto tcp from { 127.0.0.0/8 [on-link/24] } to any port { 80 443 } flags any no state
pass in quick inet6 proto tcp from { ::1 } to any port { 80 443 } flags any no state
block in quick proto tcp from any to any port { 80 443 }
```

Stateless, so a narrowing is judged packet by packet and cuts connections
the wider mode admitted. Blocking every destination, so an address the host
gains later is covered without a reload; the cost, accepted, is that the
host also stops forwarding these two ports for others (Internet Sharing,
VMs on shared networking). pf is enabled by reference token now, and at
boot by a LaunchDaemon, because macOS loads `/etc/pf.conf` at boot and
leaves pf disabled. Loading the anchor is the one root step: `janus mode`,
and `autostart` write their files as the user and run
`sudo janus firewall`, which reads the user's scope through `SUDO_UID`
and touches only `/etc` and `/Library`. Root never writes under a user's
home. The edge refuses to serve `localhost` or `lan` until the anchor
files are in place, so an unprivileged install is never a wildcard socket
with nothing scoping it.

**Windows** is refused loudly; exposure modes are a follow-on there.

## The interface for `lan`

The interface is the default route's, read from `route -n get default`
on macOS and `/proc/net/route` on Linux, and stored with the address and
its on-link prefix. `--interface` pins another and a later `mode lan`
keeps the pin; `--interface auto` returns to the default route. There is
no separate repair verb: after DHCP or the default route moved, `janus
mode lan` again is the repair. The address is never
guessed among several: two private addresses on one interface require
`--v4`. Tunnels, bridges, VM fabrics, and Apple's peer links are never
candidates; a `/32` host route is not a subnet and is refused.

## Measured on 2026-09-06

Connection attempts, not `lsof`, from four vantages: pop (the macOS host),
pup (a Linux peer on the same /24 and /64), live (public IPv4). Refused and
timeout both count as BLOCK.

| mode | pop loopback (v4 and v6, 80 and 443) | pup, 10.0.0.211 | pup, pop's three global IPv6 | live, public v4 |
| --- | --- | --- | --- | --- |
| `localhost` | PASS | BLOCK | BLOCK | BLOCK |
| `localhost`, alias `10.0.0.250` added after the anchor loaded | — | BLOCK on both addresses | — | — |
| `lan` (en0 from the default route, no flag) | PASS | PASS, TLS for `rip.local` verifies | BLOCK | BLOCK |
| `lan` → `localhost` with a keep-alive connection held from pup | — | last response one second before the change, none after; the connection stalls | — | — |
| `wan` | PASS | PASS | — | BLOCK by NAT |

Baseline before the anchor, for contrast: pup reached pop on both IPv4 and
IPv6 in every mode. DNS was never a boundary; a crafted SNI was served.

## Doors closed

Each of these was tried or designed and is recorded here because it read
as sound and was not.

- **pf `(self)` is never populated on macOS.** It parses, `pfctl -sr`
  prints it, and the block matched zero packets while pup connected; pf's
  skip steps did not even evaluate the second rule. `self` without
  parentheses is a load-time snapshot of the host's addresses, so it fails
  open on the next DHCP lease or network join. Only `to any` holds.
- **An empty `default_bind` is the wildcard** in Caddy 2.11, not a parse
  error, and a placeholder with a default cannot be caught by `validate`
  either. The mode cannot rely on the Caddyfile refusing; the in-process
  derivation plus the socket watch are what keep the bind honest.
- **`lan` with IPv6 needs a firewall on every platform,** because a
  global IPv6 address is routable from the internet and Linux cannot
  express "this address, on-link peers only" by binding. It also needs
  per-platform readers for DHCPv6 and SLAAC flags and an ambiguity prompt
  for hosts with several global addresses. Dropping IPv6 from `lan` is
  what made Linux firewall-free and the whole design small.
- **A bind carried in the env file** is a second source of truth that can
  disagree with `scope.json`, and Caddy's `reload` has no `--envfile` to
  read it anyway. The bind is derived, never stored.
- **`DynamicUser=yes` on the system unit** resolves the edge's paths as a
  non-root user under `HOME=/var/lib/janus`, so it reads the wrong scope
  file, and it hides the control socket under a root-only `private/`
  tree. Running the system edge unprivileged is its own change, not a
  rider on this one.
- **Root writing under a user's home,** even chowned back, is a confused
  deputy under a restricted sudoers line (a symlinked `scope.json`) and
  leaves root-owned directories behind on a fresh Mac. Escalate for the
  privileged step only.
- **A watch that keeps the scope it read at start** kills a legitimate
  mode change two seconds after the reload. It rereads the file, and it
  tolerates the one tick in which a reload is in flight.

## Local names in wan mode

The local name families — `<name>.local`, `<name>.localhost`, and
`localhost` — are for a machine you sit at and a network you are on. A
public address has neither, and a request that carries one of those names
in its Host header at a public address is someone asking the wrong
question, so in `wan` the edge does not answer it:

- The janus site handler answers **421 Misdirected Request** for any such
  Host, the mdns front door included, before anything else looks at the
  request.
- The on-demand permission (`permission janus`) refuses those names, so no
  certificate is minted for them.
- The mdns advertiser's desired set is empty: the periodic pass withdraws
  what is on the air with goodbyes, and re-announces when the mode
  returns. `/1.0/mdns` carries `"exposure":"wan"`.
- `janus serve` refuses with the reason; it has nothing to open.

The module learns the mode from the process that runs it: the service
edge publishes the stored scope (`janus.SetExposureScope`) when it starts
and on every pass of its exposure watch, so `janus mode wan` takes effect
on the running edge within a watch tick, and `janus mode lan` brings the
names back the same way. A Caddyfile run some other way publishes
nothing, which reads as the default, `localhost`, and keeps its local
names: the acceptance fixture and a developer's high-port config are not
service edges.

The seed's local sites stay in the file in every mode. They are inert in
`wan` without editing, and they work again the moment the mode narrows.
