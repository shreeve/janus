# TLS ask: on-demand certificate allowlist

Hot `/1.0` surface riding the existing **control** capability — not a new
cold capability. Caddy's On-Demand TLS asks Janus before minting a
certificate; Janus answers from the apps registry.

| | |
| --- | --- |
| **Phase** | 6 (build SPEC) |
| **Surface** | Hot `/1.0` (control listeners) + stock Caddyfile TLS grammar |
| **Cascades** | n/a — not a cold capability |
| **Module** | `janus` app (`control_api.go`); registry (`apps.go`) |
| **Endpoint** | `GET {base}/1.0/tls/ask?domain=<name>` |
| **Status** | Served on every control listener |

## Why it exists

Cold Caddyfile config owns the TLS machinery: listeners, issuers, ACME,
and which sites opt into on-demand minting. What it cannot know is
*which names are legitimate right now* — that is registry state. The ask
endpoint is the one-question bridge: **may we mint for this name?** The
hot registry answers; it never touches listeners or issuers.

## Contract

Checked top to bottom:

| Request | Response |
| --- | --- |
| `domain` missing or empty | **400** |
| The edge is in `wan` mode and `domain` is a local name (`localhost`, `<name>.localhost`, `<name>.local`, `via.rip`, `<name>.via.rip`) | **404** — never certified in `wan`, whoever claims it |
| `domain` resolves to a registered app: an exact host, a site-pattern alias, or a directory-gated site-pattern host whose site directory exists | **200** `{"domain":"…","app":"<id>"}` |
| `domain` is a cold browse claim (an exact host a cold `browse` root reserves) | **200** `{"domain":"…","claim":"cold"}` |
| `domain` is the mdns front door's own name (configured, conflict-renamed, or canonical) | **200** `{"domain":"…","claim":"cold"}` |
| Anything else | **404** `{"error":"domain \"…\" is not a host of any registered app"}` |
| `HEAD` | The `GET` answer's status and headers, no body (Go's `GET` route serves `HEAD`) |
| Any other method | **405** |

Caddy allows minting on **200** and denies on any other status. Janus
answers **404** for names it does not claim — the same status the data
plane gives an unknown host, and the same "there is no such resource"
meaning as an unknown app id. (403 would imply an authenticated caller
was refused; nothing here is about the caller.)

### Matching

- **Data-plane resolution.** The ask resolves `domain` exactly as the
  data plane resolves a request's `Host`: it must be a syntactically
  valid DNS name (an optional numeric `:port` is dropped), it is
  lowercased with any trailing dot stripped, and it is looked up as an
  exact registered host or site-pattern alias, then against registered
  site patterns. A pattern host (`<site>.<suffix>`) is allowed only
  while `<site>` is a direct, non-symlink child directory of the
  registration's site directory — the same live gate that admits its
  requests — so removing the directory withdraws the allowance.
- **Cold claims.** Hosts that cold config reserves for itself — exact
  hosts of a cold `browse` root and the mdns front door's names — are
  allowed without any registration; their body says `"claim":"cold"`
  instead of naming an app.
- **No wildcard names.** Host validation rejects `*` in any label, so a
  wildcard host never enters the registry and a wildcard ask never
  matches. A site pattern is not a wildcard certificate: each concrete
  `<site>.<suffix>` name is asked, and minted, on its own.
- **Exposure first.** In `wan` mode the local name families are refused
  before any lookup, matching the data plane's 421 for them.

### Lifecycle

Allowance is registry membership (plus the cold claims above) — nothing
separate to manage:

| Transition | Ask answer |
| --- | --- |
| `POST /1.0/apps` (host claimed) | 200 |
| `DELETE /1.0/apps/{id}` | 404 |
| Heartbeat TTL reap | 404 |
| A pattern host's site directory removed | 404 |
| Alive but not routable (`upstreams []`, fresh heartbeats) | **200** — heartbeat ≠ readiness; a reload never breaks TLS |

### Auth

The ask rides the control listeners with the same Bearer behavior as
every `/1.0` route. Caddy's `ask` request carries no Authorization
header, so point it at a listener without `token:…`. Pointing it at a
tokened listener denies every mint with 401 — loud, visible in both
logs, nothing minted silently.

### In-process form

`tls.permission.janus` is the same decision without the HTTP hop: Caddy
calls the module, the module asks the janus app's registry, and no
control listener is needed for it. `permission janus` in the global
option selects it; the module resolves the janus app at ask time, so
the tls and janus apps load in any order, and a config with no janus
app denies every mint rather than minting unchecked.

## Cold config

Normal Caddy grammar only — no new directives. The global option names
the permission; each site opts in per stock `tls` syntax:

```caddyfile
{
	on_demand_tls {
		permission janus
	}

	janus {
		control local
	}
}

# Public: ACME issuers mint on demand for registered hosts
https:// {
	tls {
		on_demand
	}
	janus
}
```

The repo-root `Caddyfile` demonstrates the path with the internal CA on
`:8443` (no ACME dependency):

```caddyfile
https://:8443 {
	tls {
		on_demand
		issuer internal
	}
	janus
}
```

One sharp edge to know: Caddy consults its certificate cache **before**
on-demand. A name already covered by a cold-loaded certificate (e.g. the
working tree's `*.janus.localhost` wildcard) is served that certificate and the ask
never fires. The ask path is exercised by names the cold config does not
cover — which is exactly its production role.

## Verify

```bash
go test ./...
./test.sh   # tls group

# By hand, against the running root Caddyfile:
curl -s -o /dev/null -w '%{http_code}\n' \
  'http://127.0.0.1:7600/1.0/tls/ask?domain=demo.janus.test'   # → 404

curl -s -X POST -H 'Content-Type: application/json' \
  --data '{"name":"demo","hosts":["demo.janus.test"]}' \
  http://127.0.0.1:7600/1.0/apps                               # → 201

curl -s -o /dev/null -w '%{http_code}\n' \
  'http://127.0.0.1:7600/1.0/tls/ask?domain=demo.janus.test'   # → 200

# Handshake: cert minted on demand from the internal CA
echo | openssl s_client -connect 127.0.0.1:8443 \
  -servername demo.janus.test 2>/dev/null |
  openssl x509 -noout -issuer -ext subjectAltName
# → issuer=…Caddy Local Authority…, DNS:demo.janus.test
```

## Hard errors

- Missing or empty `domain` → 400
- Any method but `GET` or `HEAD` → 405
- Wildcard hosts rejected at registration, so never allowed here
- A local name in `wan` mode → 404, whatever claims it

## Non-goals

- Per-app issuer or TLS policy (cold config owns the machinery)
- Wildcard allowances
- Persisting allowances (registry is memory-only; tenants re-register)
- Rate limiting the ask (Caddy already rate-limits on-demand minting)
