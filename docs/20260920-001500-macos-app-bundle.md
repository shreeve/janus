# Janus as a macOS application bundle

Contract for shipping the macOS edge as `Janus.app`. Not a capability:
like the exposure modes, this is the binary's and the installer's job,
and it changes no directive and no `/1.0` surface.

## Why it exists

macOS 15 and later identify a program for Local Network privacy by its
code signature and its bundle. A bare executable has no bundle, so the
Settings row shows the executable's file name or signing identifier with
the generic Unix-executable icon, and the permission prompt, when macOS
shows one, cannot say what the program is or why it wants the network.
An application bundle gives macOS what it is built around: a bundle
identifier, a display name and icon, and a usage description. This
contract makes the bundle the unit that is installed, launched, and
upgraded for a user's edge on macOS, while the `janus` command on PATH
keeps working unchanged. The background is
[macos-local-network-privacy](20260919-225500-macos-local-network-privacy.md).

Apple documents an ad-hoc signature as the case Local Network privacy
tracks least reliably and names an Apple-issued signing identity as the
remedy. The bundle improves the row, the prompt, and the identity macOS
sees; it does not remove that caveat, and Apple signing stays possible
later without changing anything here.

## Scope

A user's edge on macOS. Root's edge (`sudo janus autostart`) is a launchd
daemon, which macOS exempts from Local Network privacy, and a system
service must not run from the group-writable `/Applications`; root keeps
the bare binary at `/usr/local/bin/janus`. Linux and Windows installs,
archives, and service items do not change. Cascade: not applicable.

## The bundle

```
Janus.app/
  Contents/
    Info.plist
    MacOS/janus            the same build as the bare binary; its signature is the bundle's
    Resources/Janus.icns   from docs/janus-1024.png when present, else docs/janus-circle.png
```

`Info.plist` keys, all fixed except the two version strings:

| Key | Value |
| --- | --- |
| `CFBundleIdentifier` | `com.github.shreeve.janus` |
| `CFBundleName`, `CFBundleDisplayName` | `Janus` |
| `CFBundleExecutable` | `janus` |
| `CFBundleIconFile` | `Janus.icns` |
| `CFBundlePackageType` | `APPL` |
| `CFBundleShortVersionString` | the release version as `x.y.z` (`1.17.0`); a dev build's leading `x.y.z`, or `0.0.0` |
| `CFBundleVersion` | the full version string as `janus version` prints it |
| `CFBundleInfoDictionaryVersion` | `6.0` |
| `LSUIElement` | `true`: a LaunchServices launch (a double-click after `lsregister`) shows no Dock icon; it runs `janus` with no arguments and exits |
| `NSLocalNetworkUsageDescription` | `Janus announces this Mac's local names (janus.local and each app's .local name) and answers the devices on your network that look them up.` |

The icon is built with `sips` and `iconutil` at the sizes the source
fills without upscaling: from a 1024 px master every size `iconutil`
knows; from the 320 px circle the sizes up to 256 px.

Signing is ad hoc: the executable with `--identifier
com.github.shreeve.janus`, then the bundle with no identifier argument,
so it takes `CFBundleIdentifier` and the two cannot disagree. Nothing in
the bundle is written after signing. The identifier never changes.

## Locations

| | User | Root |
| --- | --- | --- |
| Bundle | `~/Applications/Janus.app` | none |
| Command on PATH | `~/.local/bin/janus`, a symbolic link with the absolute target `~/Applications/Janus.app/Contents/MacOS/janus` | `/usr/local/bin/janus`, the bare executable |

`BIN=` moves the command as today; the bundle location is not
configurable in v1. `~/Applications` is created when absent.

## Installers

`scripts/release-install.sh` (inside every archive, and `make install`)
and `install.sh` behave the same on macOS:

1. Build or receive the bundle. The osx-arm64 archive contains `Janus.app`
   and a relative `janus` symlink into it, so the extracted archive runs
   in place before it is installed. `make install` builds the bundle from
   `bin/janus` with `scripts/bundle-macos.sh`.
2. Verify the source: signed as `com.github.shreeve.janus`, or refuse.
3. Copy the whole bundle (`ditto`) to a staging directory beside the
   destination; refuse if the copy carries `com.apple.quarantine`;
   `codesign --verify --strict` the copy; `touch` its executable so
   `janus status` sees a newer binary than the edge it compares with.
4. Swap: move an existing `Janus.app` aside, rename the copy into place,
   remove the old one. Nothing is ever written into an existing bundle:
   a running edge keeps its unlinked executable, and no inode macOS has
   cached is overwritten.
5. Replace `$BIN/janus` with the symlink by renaming a staged link over
   it. A regular file there (a bare install) is replaced the same way,
   and the installer says that a running edge keeps it until `janus
   restart`.
6. Register the bundle with LaunchServices (`lsregister -f`), best
   effort, so Settings shows the name and icon at once.

As root, the installers take the executable out of the bundle, install
it as the bare binary, and sign it again on its own. On Linux the
installer is unchanged. `install.sh --uninstall` refuses while the
service item is installed (`janus autostart off stop` first), then
removes the command and, for a user, the bundle.

## The service item

`janus autostart` registers the executable inside the bundle when the
invoked command resolves into `Janus.app/Contents/MacOS/`, and the item
carries `AssociatedBundleIdentifiers` naming the bundle, so launchd starts
the bundle's executable directly and macOS attributes the process to the
bundle. A bare binary is registered by its invoked path as today.

`janus restart` under the item compares the item's file with what it
would register now and, when they differ, rewrites the file and reloads
the item instead of kicking the old spec, saying so. An install that
moved the edge into the bundle behind the same command name therefore
takes effect at the next restart with no separate step.

The item's `PATH` begins with the bundle's `MacOS` directory rather than
the command's directory; nothing depends on the difference.

## Upgrading a bare install

The first bundle install on a Mac with a bare `~/.local/bin/janus`
replaces the file with the symlink and leaves the old Local Network row
for the bare binary behind, inert; macOS has no way to remove it. The new
"Janus" row appears at the edge's next start, which `janus restart`
performs from the bundle; turn the row on once and restart again. The
operator contract states this.

## Hard errors

- The source bundle is signed under another identifier, or not at all:
  refuse, name both.
- The bundle destination exists and is not a directory containing
  `Contents/Info.plist`: refuse, name the path.
- `~/Applications` cannot be created or written: refuse.
- The copied bundle carries `com.apple.quarantine`: refuse, print
  `xattr -dr com.apple.quarantine <source>`.
- `codesign --verify --strict` fails on the copy: refuse before anything
  is renamed into place.
- `$BIN/janus` is a directory: refuse.
- Building the bundle without `sips`, `iconutil`, `codesign`, or
  `plutil`: refuse; all ship with macOS.
- Uninstall while the service item is installed: refuse, name the verb.

## Non-goals (v1)

- Apple-issued signing or notarization.
- A GUI, a Dock presence, or anything meant to be double-clicked.
- A configurable bundle location, or a bundle for root.
- Changing `janus status`: its `binary` field is the path the status
  command was invoked as, the symlink on a bundle install; `binary_newer`
  compares the resolved file's mtime, which step 3 keeps meaningful.

## Tests

- `install_test.go`: on a mocked Darwin, the installer produces the
  bundle layout and the symlink from a bundle path and through the
  archive's symlink; an existing bare binary becomes the symlink; an
  upgrade swaps the bundle; a non-bundle at the destination, a foreign
  identifier, and a quarantined copy are refused; root receives the bare
  executable, re-signed.
- `cmd/janus`: `bundleExecutable` resolves a symlink into the bundle and
  leaves other paths alone; `launchdPlist` names the bundle only for a
  bundled executable; `restartEdge` rewrites and reloads a stale item and
  leaves a current one to the manager's restart.
- `release.yml` smoke test: the installed command is a symlink into the
  installed bundle, whose executable matches the packaged one, whose
  signature verifies with the identifier, and whose `Info.plist` carries
  the tag's version.
- `test.sh` is unaffected.

## Acceptance on a Mac

Install, `janus autostart`, then: System Settings → Privacy & Security →
Local Network shows one row named Janus with the icon; `dns-sd -B
_http._tcp` shows `janus` on the LAN interface; a live multicast query for
the announced name is answered; `janus status`, `restart`, `stop`, and
`start` behave as before. No throughput claim is made or measured.

Observed 2026-09-20 on macOS 27.0 after a Local Network reset and reboot:
one rule for `com.github.shreeve.janus` with no path component (the form
macOS records for a bundle, not an executable), set to allow without a
prompt; the edge running from `Janus.app/Contents/MacOS/janus` under
launchd; `janus` visible on the Wi-Fi interface in `dns-sd -B`;
`janus.local` resolved and served over HTTP and HTTPS; every service verb
working through the symlink.
